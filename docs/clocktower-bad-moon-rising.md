# 피로 물든 달 진행 도우미

## 지원 범위

- 진행방 준비 단계에서 점철되는 혼란 / 피로 물든 달을 선택합니다. 변경 시 역할 배정과 비밀 준비 정보를 초기화합니다. 진행 중인 기존 게임은 변경하지 않습니다.
- 새 방은 이벤트 제목에 `피로 물든 달`이 있으면 해당 시나리오로 시작합니다.
- 25개 캐릭터, 5~15인 구성, 대부의 외지인 ±1, 무작위 배정 초안과 개별 편집을 지원합니다.
- 사용자 제공 한국어 밤 시트의 첫 밤 / 이후 밤 순서를 안내합니다. 조건을 확인한 후 요청·판정·다음 차례를 진행합니다.
- 0~3명 대상 선택, 캐릭터 선택, 능력 쉬기, 동일한 공통 미션 UI와 1~5초 지연을 지원합니다.
- 결과 전달과 결과 확인을 구분합니다. 전달 후 다음 차례로 갈 수 있고, 낮으로 넘어가기 전에는 결과와 미션을 모두 확인해야 합니다.
- 마도서에서 실제 사망, 부활, 좀비얼 사망 위장, 실제 진영, 취함·중독·보호·능력 소모와 원인/기간 메모를 관리합니다.
- 비밀 상태와 밤 사망은 다른 참가자에게 노출하지 않습니다. 미치광이는 설정된 악마 역할과 악한 팀 표시만 봅니다. 건달 소속 변경은 밤 비공개 안내로 전달합니다.
- 낮 지목/수동 투표, 처형 후보 산정, 이야기꾼의 처형 결과 확정과 승리 진영에 따른 플레이 이력 저장을 지원합니다. 좀비얼의 위장 사망은 유령표·생존자 수에서는 사망으로 취급합니다.

## 자동 판정과 구분

이 버전은 **이야기꾼 판정형 진행 도우미**입니다. 능력 선택만으로 사망·부활·취함·보호·능력 소모·효과 만료가 자동 계산되지는 않습니다. 원인, 적용 순서, 밤에 깨어난 이유, 이전 대상, 포 충전, 주모자 추가 낮, 험담의 참거짓과 달의 자손의 공개 선택은 이야기꾼이 판단하고 기록합니다. 상태 체크박스는 기록 표시이며 다른 명령을 자동 차단하지 않습니다. 이 경계를 화면에도 표시합니다.

참고 사진과 아카이브는 `.local-reference/clocktower/`에만 보관하며 Git/배포 자산에 포함하지 않습니다.

- 기존 밤 엔진/역할 구성/정보 준비/결과 전달 후 진행 테스트, TypeScript, 변경 파일 ESLint, production build.

## 2026-09-26 확장 검증

재실행: `node tests/run-clocktower.cjs` (PGlite 위치는 `PGLITE_MODULE`로 지정 가능). 상세 실행 결과는 비공개 `.local-reference/clocktower/test-results/latest.json`에 저장됩니다.

- 피로 물든 달 5~15인 **유효한 역할 집합과 미치광이 표시 역할 2,499,068조합**을 열거했습니다. 좌석의 모든 순열과 모든 밤 판정의 조합을 열거한 것은 아닙니다.
- 분리된 PostgreSQL에 기존 시계탑 마이그레이션 전체와 새 변경을 적용하여 **7,369개 단언**을 통과했습니다. 거부되어야 할 잘못된 요청의 거부도 포함합니다.
  - 인원·대부 구성 108가지의 클라이언트/서버 일치
  - 25역할 × 생존/사망/위장 × 소속 × 16개 상태 표시: 1,632가지
  - 0~3인 선택 × 캐릭터 선택 × 쉬기 × 본인 선택: 32가지 형식
  - 미로그인·다른 회원·참가자 권한, 오래된 요청, 중복 제출, 취소, 일괄 저장 롤백, 부활 후 투표권, 복기 접근
  - 처형 없음·부족한 표·동률·단독 최다·생존·사망·위장 및 다음 밤 전환
  - 25역할 × 2소속 × 2승리 진영의 결과 저장 100가지
- 화면 상태 테스트에서 편집 창을 연 후 폴링으로 서버 상태가 변경되어도 최초 버전으로 저장을 검증하여 덮어쓰기를 막고, 종료된 메모는 읽기 전용임을 확인했습니다.

발견 후 수정한 문제:

1. 낮에서 다음 밤으로 넘어갈 때 `n` 변수/집계 열 이름이 겹치는 PostgreSQL 오류를 수정했습니다.
2. 역할·메모·무작위 배정·승리 판정·페이즈 확인 창의 오래된 입력이 최신 버전 번호로 덮어써지지 않도록 편집 시작 버전을 보존했습니다.
3. 종료된 게임의 메모 저장 버튼을 제거하여 불가능한 저장 요청을 막았습니다.

검증 경계: 능력 효과를 자동 판정하는 엔진은 이 버전에 없습니다. 상태 플래그 저장 테스트는 선원·건달·음유시인 등의 모든 규칙 상호작용을 자동 판정했다는 뜻이 아닙니다. DB는 PGlite이며 다른 서비스 테이블은 최소 스키마로 구성한 격리 환경입니다. 요청 재전송·순서·버전 충돌은 검증했지만 실제 병렬 DB 연결과 여러 휴대폰의 동시 접속, 브라우저 시각 확인 및 운영 DB 적용 후 검증은 아직 수행하지 않았습니다.

최종 재실행 결과: `node tests/run-clocktower.cjs` 23개 테스트 묶음 전부 통과, 실패 0개. 변경 파일 ESLint와 TypeScript를 포함한 production build도 통과했습니다. 운영 DB 및 사이트는 변경하지 않았습니다.
